# 複数語句のAND検索

## CLIと条件

```sh
zigurui search --mode normalized --all .local/normalized.idx '検索エンジン' '高速化'
zigurui scan --mode normalized --all /path/to/notes '検索エンジン' '高速化'
zigurui search --all .local/notes.idx 'a b' '--all'
```

`search` と `scan` の入力パス前に `--all` を置く。`--mode` を指定する場合はサブコマンド直後、その後に `--all` を置く。入力パス以降はすべて検索語句で、`--all` などの文字列も通常の語句となる。入力名そのものが `--all` の場合は `./--all` と指定する。`index` は `--all` を受け付けない。

各引数は独立した連続部分一致条件で、すべてを同一文書が満たしたときだけ1件返す。語句の順序は問わず、出現範囲は重なってよい。空白分割、trim、単語境界の判定はしない。`'a b'` は空白を含む一つの語句で、`a b` の二引数とは異なる。`--all` を付けない従来の単語検索はそのまま利用できる。

literalは原文、normalizedは[検索の正規化](search-normalization.md)の表現で照合する。normalizedは各語句を変換した後の同値を除き、最初の入力を残す。literalも同じバイト列の重複を除く。全角空白などの扱いも正規化の契約に従う。

入力パスがあって検索語句が0個の場合、空語句の場合は `EmptyQuery`。不正UTF-8は `InvalidUtf8`。全語句の検証と変換を終えてから索引を調べるため、先頭語のpostingが存在しなくても後続の不正な語を見逃さない。APIの空配列も `EmptyQuery`。入力パスがない場合は `InvalidArguments`。

## 代表位置と表示

各語句について検索表現で最初の一致を選び、原文のUTF-8バイト区間へ復元する。その中で原文開始位置が最小の区間を代表として表示する。同じ開始位置の場合は入力順で最初の語句を使う。全出現を探して原文で最初の位置を選ぶ仕様ではない。

例: `前㌔後 ｶﾞ` に対して `ガ` と `ロ` を指定すると、語句順に関係なく `㌔` の原文区間 `[3, 6)` が代表になる。`ab` に `ab`、`a` の順で指定すると `[0, 2)`、逆順なら `[0, 1)`。結果は従来どおり文書パス順で、行番号・抜粋は原文から作る。抜粋は代表位置の周辺だけなので、他のAND語句が同じ抜粋内に現れるとは限らない。

## 候補抽出と所有権

全語句の2-gramから最短postingを種にして、全語句の全gramがある文書を候補にする。1コードポイントの語句も候補本文で必ず確認する。全語句が検索表現で1コードポイントの場合は全文走査する。normalized索引のliteral検索も従来どおり保存原文を全文走査する。

検索語句は呼び出し中に一度ずつ準備し、候補本文は一度だけ正規化する。語句ごとの最初の一致位置を検索実行中の配列へ記録し、全語句の成立後にだけ原文区間を復元する。この配列は文書ごとに確保し直さない。

`Index.searchAll(allocator, terms, mode)` と `Index.scanAll(allocator, terms, mode)` は入力を呼び出し中だけ借用する。返す `[]Match` は呼び出し側が同じallocatorで解放する。索引形式v2と保存内容は変更しない。

独立期待結果と性能スモークの記録は[AND検索の評価](search-and-evaluation.md)を参照。
